# Админка и статистика

Адрес: `https://<домен>/#/admin`. Админка доступна только при запущенном Node.js-сервере.

1. Сгенерируйте случайный ключ: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`.
2. Создайте `.env` рядом с compose-файлом по образцу `.env.example`, впишите `ADMIN_TOKEN=<ключ>` (минимум 32 символа).
3. Пересоберите и запустите: `docker compose up -d --build`. Для готовых образов сначала опубликуйте образы с этими изменениями, затем выполните `docker compose -f docker-compose.ghcr.yml pull` и `docker compose -f docker-compose.ghcr.yml up -d`.
4. Откройте `#/admin` и введите ключ. Он передаётся в заголовке Authorization и хранится только в памяти вкладки. Для публичного развёртывания используйте настроенный HTTPS.

Для первоначального входа нужен ключ из `ADMIN_TOKEN`: от 32 до 256 печатных символов ASCII без пробелов. Если ни корректного начального ключа, ни сохранённого ключа нет, API админки выключен. Ключ нельзя помещать в `VITE_*`: такие переменные входят в публичный frontend bundle.

## Смена ключа

После входа нажмите «Изменить ключ входа», введите текущий ключ и дважды новый. Старый ключ сразу перестаёт работать во всех вкладках. Текущая вкладка автоматически продолжает работать с новым ключом; в остальных потребуется войти заново.

На сервере сохраняется только хеш scrypt с солью в `DATA_DIR/admin-key.json`; открытый ключ не записывается и не возвращается API. Сохранённый ключ имеет приоритет над `ADMIN_TOKEN` и действует после перезапуска контейнера. Смена ключа не изменяет `.env`.

Если ключ утрачен, остановите сервер, удалите только `DATA_DIR/admin-key.json`, задайте новый `ADMIN_TOKEN` и запустите сервер. Это сбросит ключ на значение из окружения, сохранив статистику и сессии.

## Показатели

- **Заходы** — загрузки приложения, включая перезагрузки; загрузки `#/admin` исключены. Это не уникальные посетители. Блокировщики, сетевые ошибки и вызовы API вручную могут влиять на счётчик.
- **Созданные сессии** — успешное создание сессии на сервере.
- **Начатые собеседования** — первое подключение кандидата; повторные подключения не увеличивают этот счётчик.
- **Завершённые сессии** — явное завершение либо автоматическое завершение по простою. Здесь могут быть и сессии без кандидата.
- **Подключения** — входы участников всех ролей, включая повторные входы.
- **Телеметрия / предупреждения** — сохранённые события, включая серверные входы/выходы; предупреждения имеют sev `warn` или `alert`. Запись буферизуется примерно на секунду.
- **Онлайн** — текущие WebSocket-подключения. «Комнат с участниками» — активные комнаты с хотя бы одним подключением.

Фильтр 7/30/90 дней применяется к карточкам и графику; календарные сутки считаются в UTC. Языки и последние 100 сессий показаны за всё время сбора. Язык учитывается при создании сессии. Длительность — время от первого подключения кандидата до завершения, включая периоды без участников.

Данные записываются в `DATA_DIR/analytics.json`, сохраняются при перезапуске и не удаляются при очистке файлов завершённых интервью. Агрегаты не содержат IP, имён, кода, токенов или содержимого телеметрии. Сохраняются дневные счётчики, распределение языков и краткие сведения о последних 100 сессиях.

Сбор начинается после установки этой версии. Старые сессии и события не импортируются; локальный режим без сервера не учитывается. Показатели предназначены для базовой статистики, не для аудита: при сбое диска или аварийной остановке последние изменения могут не попасть в агрегаты. Ошибка записи статистики не блокирует сохранение самого интервью.

## Локальный запуск

В отдельном терминале задайте `ADMIN_TOKEN` в окружении, перейдите в `server`, выполните `npm install`, затем `npm start`. В корне проекта выполните `npm install` и `npm run dev`. Vite проксирует `/api` и `/ws` на порт 8090. Страница админки: `http://localhost:3000/#/admin`.

Проверки: `npm run build` в корне и `npm test` в `server`.
